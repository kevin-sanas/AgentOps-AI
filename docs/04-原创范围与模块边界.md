# 04｜原创范围与模块边界

## 原创内容和二开界线

原创范围：服务目录及目标安全策略、探测作业、失败去重和事故状态机、事故/运行手册数据模型、LangGraph 诊断节点和只读工具、审批记录、Kuma Push adapter、评测场景、UI 和运维规程。Uptime Kuma、LangGraph、Spring Boot 等均为外部依赖，不复制其代码或把其商标当作产品名称。

本项目不 fork 或修改 Uptime Kuma。集成是单向推送状态到人工创建的 Push Monitor；外部 API 的变化由隔离适配器承接。

## 组件职责

| 组件 | 职责 | 不做 |
|---|---|---|
| Vue SPA | 服务/事故/诊断/审批视图 | 探测目标、内部密钥、权限最终判断 |
| Spring Boot | 用户、RBAC、目标、检查策略、调度结果、事故、手册、Outbox、审计 | Agent 图逻辑或命令执行 |
| FastAPI + LangGraph | 消费受限诊断请求，读允许数据，运行图，输出结构化建议 | 公开登录、访问任意互联网、修改监控目标或执行 shell |
| PostgreSQL | 业务/事故/任务/审批/图 checkpoint 存储 | 对外暴露给 LLM 或前端 |
| Uptime Kuma | 可选显示被推送的 Push Monitor 状态与发送自己的通知 | AgentOps 事实库、事故控制面、Kuma 配置同步源 |

## 建议模块

```text
backend: identity / access / targets / checks / incidents / runbooks /
         agent-orchestration / integrations / jobs / audit / shared
agent-service: graph / nodes / tools(read-only) / schemas / checkpoint /
               prompt / evaluation / internal_api
frontend: auth / overview / targets / incidents / runbooks / agent-runs / settings
```

Java 是跨模块业务事实来源；Python 通过内部 DTO 接收最小上下文与资源 ID。LangGraph checkpoint 与业务表使用不同 schema；检查历史摘要由 Java 授权查询后传入 agent，不给 Python 任意 SQL 账号。
