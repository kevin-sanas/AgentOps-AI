## 简历描述模板

> 独立设计实现 AgentOps AI 智能运维平台：Spring Boot 管理服务目标、HTTP 健康检查与事故状态机；Python/FastAPI + LangGraph 构建受控只读诊断图，并使用 PostgreSQL checkpointer、Outbox 和幂等处理异步运行；Vue 3 实现事故/审批工作台；以可选 Uptime Kuma Push adapter 展示检查状态。诊断评测【填写实际场景数、证据引用准确率、失败案例】，系统性能【填写测试环境及实测数据】。

模板只能填入真实完成事项和实测值。不要写“自动修复生产故障”“零风险”或没有证据的性能数字。

## 演示脚本与答辩

1. 用 fixture 目标制造 3 次 503，展示检查历史和自动聚合事故。
2. 以 ON_CALL 启动诊断，展示运行阶段、事实/假设、check/runbook 引用。
3. 拒绝建议，再演示人工审批只改变审计/状态，不执行命令。
4. 恢复 fixture，展示同一事故恢复、关闭和完整时间线。
5. 可选启用 Kuma profile，展示预建 Push Monitor 收到状态；停止 Kuma 后确认 AgentOps 记录完整。

面试重点：怎样防 SSRF、为什么 Java 是事实源、LangGraph checkpoint 如何恢复、Outbox 与幂等如何避免重复执行、为什么 Kuma API 不做双向绑定、为什么 Agent 不执行命令。
