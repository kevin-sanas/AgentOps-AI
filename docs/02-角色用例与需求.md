# 02｜角色、用例与需求

## 角色

| 角色 | 能力 | 限制 |
|---|---|---|
| `OBSERVER` | 读获授权服务、检查历史和事故 | 不能编辑服务/运行手册或启动 Agent |
| `ON_CALL` | 认领/确认事故、添加时间线、启动只读诊断、审阅建议 | 不管理用户/策略；没有系统执行命令能力 |
| `OPS_ADMIN` | 用户与角色、服务目标、检查策略、运行手册、集成配置 | 所有目标/secret 配置/审批策略变更均审计 |
| `AUDITOR` | 只读访问审批、操作审计和运行摘要 | 不读取 secret 原值，不改变事故 |

角色按最小权限授予；`OPS_ADMIN` 不自动等于 `ON_CALL`。可通过资源授权控制哪些人读哪些服务与事故。

## 用例

| ID | 用例 | 验收 |
|---|---|---|
| UC-01 | 管理员登记 HTTP 服务 | URL/目标策略通过 SSRF 校验；生成检查定义和审计记录 |
| UC-02 | 检查调度器执行 | 结果保存状态码、耗时和脱敏错误；不保存认证头/完整响应正文 |
| UC-03 | 事故聚合 | 连续失败达阈值打开一个 incident；恢复后加入恢复事件，不重复打开 |
| UC-04 | 值班人员确认事故 | 状态变更有 actor/time/reason；并发修改返回 409 |
| UC-05 | Agent 诊断 | `202 + runId`；图按只读步骤运行；建议引用证据 ID 和运行手册版本 |
| UC-06 | 人工审阅建议 | 拒绝/接受/标记已手工执行均记录理由；“接受”不会执行命令 |
| UC-07 | 管理员接入 Kuma | 手工建 Push Monitor、录入 token；状态变化推送；超时失败不阻断本地事故 |
| UC-08 | 审计查询 | 审计员按 actor/服务/incident/run/time 过滤，无 secret/plain prompt |

## 功能需求

- `FR-01` 身份：登录、停用、角色和资源策略；会话有效期可配置。
- `FR-02` 目标：管理员录入协议、URL、期望状态码、超时、间隔、失败阈值、允许网段策略。
- `FR-03` 检查：HTTP GET/HEAD 白名单；记录开始/完成时间、状态、RTT、错误类别；限流和并发上限。
- `FR-04` 事故：按规则生成、去重、确认、处理中、解决、关闭、事件时间线。
- `FR-05` 手册：版本化 Markdown 内容，授权服务关联，变更留审计。
- `FR-06` Agent：结构化输入/输出，证据引用，超时/失败/重试可见，支持人工审批状态。
- `FR-07` 集成：Kuma Push adapter 可暂停/重试/显示健康；记录外部投递状态但不将 Kuma 当主库。
- `FR-08` 审计：服务目标/secret 配置、手册发布、事故和 Agent 审阅均记录 actor/time/requestId。

## 目标范围与人工执行语义

所有目标级对象（检查历史、事故、运行手册、Agent run）沿用 `target_access` 用户授权：`OBSERVER` 需要 `can_read=true`，`ON_CALL` 还需要 `can_operate=true` 才能处理事故/审阅 Agent；`OPS_ADMIN` 可全局配置但配置行为仍审计；`AUDITOR` 可看全局审计元数据，读取目标内容仍需要目标 `can_read`。Agent 建议审批分两步：接受后标为 `APPROVED_FOR_MANUAL`，这只代表人同意按建议在线下处理；之后调用“人工处理结果”记录 `EXECUTED/NOT_EXECUTED/FAILED`、操作者和说明，AgentRun 才结束。拒绝转为 `REJECTED`；任何状态都不触发平台执行命令。

## NFR 和边界

- 核心工作台在 LLM 不可用时仍可读写；诊断失败可见且可重试。
- 同一服务探测默认最短 60 秒；请求超时 3 秒；最大重定向 0；响应体读取上限 64 KiB 且不存正文。
- 目标域名必须经管理员登记和出站策略验证；禁止访问云 metadata/loopback/link-local；私有网段仅在管理员显式配置且网络策略允许时可访问。
- 日志正文、Header、Token、完整提示和原始响应默认不落库；所有拟定性能目标参见阶段门文档。
