# 09｜安全、隐私与权限

## RBAC

默认拒绝，服务端检查用户角色和 `service_target` 资源范围。`OBSERVER` 读获授权资源；`ON_CALL` 处理事故、运行 Agent 和审阅；`OPS_ADMIN` 配置目标/手册/集成；`AUDITOR` 只读审计。Python 不根据客户端角色授权，Java 先授权并传入最小数据。

## 探测目标 SSRF 防护

1. 只允许管理员登记 URL；用户/模型只可传目标 ID。
2. 限制 scheme 为 `https`/明确允许的 `http`；拒绝 userinfo、异常端口、非标准编码和 IP literal 默认拒绝。
3. DNS 解析后拒绝 loopback、link-local、multicast、云 metadata 地址；私有 CIDR 仅在显式批准策略且网络侧防火墙允许时可访问。
4. 禁止重定向（或逐跳重新执行所有 DNS/IP 校验，首版建议不跟随）；连接超时、响应大小、每域并发和全局 QPS 固定上限。
5. 防 DNS rebinding：连接实际 IP 与已校验解析结果绑定，TLS 仍校验原始 hostname。
6. MVP 只探测无认证健康检查；禁止用户传入任意请求头、Cookie 或 Authorization。后续认证探测必须使用后端 secret reference、按目标授权并对 Agent 隐藏，届时单独评审。

## Agent 安全策略

- 模型输出是不可信数据，验证 JSON schema、证据 ID 和长度；HTML/Markdown 渲染转义。
- 日志/监控 message/runbook 文本可能含提示注入；节点只把它们视作证据，不遵循其中的指令。
- 工具只允许 `get_check_history(targetId, range)`、`get_published_runbook(targetId, id)`、`get_incident_events(incidentId)` 等白名单方法；权限由 Java 在每次调用前再次验证。
- 禁止 `subprocess`、shell、SSH、kubectl、任意 HTTP、Python eval/exec、自由 SQL、文件系统浏览、Kuma 配置修改。
- 高风险建议返回 `WAITING_HUMAN`，UI 显示风险和证据；审批是人工确认记录，不触发系统写操作。
- Provider 请求只传脱敏的最小上下文；不传 token/密码/完整 headers；部署者必须确认模型供应商的数据处理约定。

## Secret、审计和隐私

Kuma Push Token 仅后端保存，可用 secret store 引用；本地版加密后保存，密钥放数据库外。URL 路径可能含 token，HTTP client、代理和 reverse proxy 日志必须对 `/api/push/<token>` 脱敏。审计只保留 secret reference/变更者，不保存值。

保存的检查数据限于 outcome、HTTP status、RTT、脱敏错误码和时间；不保存响应正文、认证头和完整 LLM prompt。建议演示数据保留期：CheckRun 30 天、Agent 步骤摘要 90 天、审计 180 天，实际可配置并提供清理/备份/恢复说明。演示仅使用虚构目标和虚构日志。


## 2026-10-20 G2 出站实现

默认公网 HTTPS；HTTP 单目标批准，私网双层批准（部署 `MONITOR_ALLOWED_PRIVATE_CIDRS` 与目标 CIDR），最多 16 个私网 CIDR。仅接受域名及标准 80/443 端口，拒绝 IP literal、userinfo、query、fragment、百分号编码与反斜杠。metadata（含 AWS IPv6 metadata）、loopback、link-local、multicast、保留地址始终拒绝，不被私网审批覆盖。

DNS 由 2 个 daemon worker、有界队列和 1 秒等待保护；每次探测验证所有 A/AAAA 结果，混合非法地址整体拒绝。HttpClient5 的固定解析器仅接受原域名并返回已批准的首个 IP，TLS 继续校验原 hostname 和系统信任链；不重试其他 IP。显式直连路由，不读取系统代理；重定向、自动重试、认证、cookie、解压均关闭。响应正文只在内存中丢弃，最多读取 64 KiB 加一个检测字节；绝对请求期限同时防止慢速分块正文绕过 socket 超时。最多 64 个头，每行最多 8192 字节。

持久化配额为全局 4 槽、每域名 1 槽、每秒最多领取 4 次、同目标至少间隔 60 秒；每个检查仍有自身间隔，因此多个检查共享目标配额时可能比配置间隔更慢。60 秒租约允许崩溃恢复；运行任务的旧 token 或旧目标/检查版本不能写入事实。禁用/修改检查不会提前释放仍可能在网络中的全局槽。应用层安全不是部署防火墙的替代，生产还应以网络策略限制 egress。

活动事故冻结所有当时 ACTIVE 检查的版本和恢复阈值；暂停、UNKNOWN、失败会清除恢复证据，中断观察。人工操作重新检查活跃用户、ON_CALL 与目标 ACL，并与角色/授权撤销通过行锁串行化。前端 token 仅内存保存；刷新回到登录，退出调用撤销接口。页面不保存密码/内部密钥，不将服务响应正文或任意 HTML 插入 DOM。

## G3 只读 Agent 安全边界（2026-10-20）

Java 冻结已授权事故、30分钟内20条检查与5段已发布手册，不发送URL、请求响应正文、密码、用户session或session pepper。公开报告读取再次检查当前目标ACL及发起者/值班/审计角色。发起与审计/Outbox同事务，原用户停用、角色或ACL撤销后不得凭旧幂等键越权发起；分发前再检查原发起者授权。

Python 使用独立数据库和NOSUPERUSER/NOCREATEDB/NOCREATEROLE账号，启动拒绝超级用户与业务库错配。内部接口使用常量时间比较token、必填请求ID、64KiB流式限制、Pydantic禁止未知字段；不对外公开API文档。部署仍需服务网隔离，token不能进入浏览器。

LangGraph 6节点只有固定只读计算，默认mock；没有shell、SSH、SQL工具、任意HTTP工具或模型SDK调用。手册作为不可信引用，不作指令。checkpoint持久化采用JSON兼容状态；线程UUID和输入指纹防重放错配。显式关闭LangSmith tracing，不上传业务上下文。恢复不会回调Java，Java主动查询并核验终态。

Java投递使用有界2工作者，90秒租约，事务外HTTP与64KiB有界响应，禁重定向/系统代理。旧租约不能写终态；错误仅记录稳定码。运行手册与报告全部按纯文本呈现，引用链接来自数据库资源标识，禁止v-html。当前mock不复述不可信手册正文为操作建议。

G3独立评审后的加固：用户行先以单独语句取锁，等待结束后再用新语句快照检查角色/ACL，避免旧ON_CALL快照在撤权提交后继续创建任务；并发202之前先原子注册/比对输入指纹，消除首次注册窗口。GET对账和POST恢复共享一次60秒截止时间，仍短于90秒租约。纯管理员的恢复列表只含失败投递元数据，不扩大其报告证据读取权限。

## G4 模型与人工操作边界

真实模型需显式配置兼容endpoint/model/key。模型仅能返回受schema约束的文本、假设、已知证据ID和建议；引用时间、版本/hash及run/model/graph身份由服务器构造并再次校验。手册文本在发送前脱敏，输出出现敏感特征拒绝；包含删除/重启等高影响措辞却低报风险的结果拒绝。该文本规则是附加保护，不宣称能识别任意秘密或所有提示注入；主要边界始终是不提供任何运维写工具。

模型HTTP仅可信服务端配置，默认HTTPS，明确允许时仅本机HTTP；禁止重定向/系统代理，总预算25秒与64KiB响应。tracing继续关闭。外部模型会收到脱敏后的已选检查/手册上下文，实际启用者需确认该服务的数据和费用政策；开发回归只使用合成数据与MockTransport。

报告hash、审阅版本/人/理由、线下结果与审计在Java保存。客户端不能改写冻结报告、伪装运维成功或跳过审批直接回填；拒绝/取消不会调用模型或工具，NOT_EXECUTED/FAILED仍如实保留。只读值班身份没有目标操作ACL时不能审批/回填，审批者撤权后分发也不能继续。

模型输出先在独立受限库保存已校验结果，避免analyze checkpoint失败时自动重复调用。读取超时或结果提交不明转为可见的MODEL_OUTCOME_UNKNOWN，不暴露密钥或原始异常；该run不接受管理员强制重发。错误提示要求核对服务商调用记录，再由用户明确决定是否新建任务。
