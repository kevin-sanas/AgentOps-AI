# 05｜架构与技术选型

## 拓扑

```mermaid
flowchart LR
  U[Vue 3] -->|/api/v1| J[Spring Boot API + Scheduler]
  J --> DB[(PostgreSQL)]
  J -->|Outbox 内网 REST| A[FastAPI + LangGraph]
  A -->|受控读工具/内部 DTO| J
  A --> DB
  J -->|Push heartbeat adapter| K[可选 Uptime Kuma]
  A --> L
  A --> L[唯一模型调用方：LLM Provider 或 mock]
```

## 数据和控制流

Scheduler 领取到期检查，访问已注册目标，存 `CheckRun` 并在事务内写 Outbox；规则引擎达到失败阈值时创建 incident。用户启动诊断时，Java 验权并创建 AgentRun/Outbox；worker 调 Python 内部 API，传 incident ID、有限时间窗口的脱敏检查摘要、runbook 版本和 runId。Python 图只读这些数据或按受限资源 ID 请求更多上下文，checkpoint 以 runId 作为 thread ID；结构化结果回 Java 保存。所有写事故/审批的操作由 Java API 完成。

## 技术基线（2026-10-20 快照）

| 层 | 选择 | 说明 |
|---|---|---|
| Java | Java 21、Spring Boot 4.1.x（观察到稳定版 4.1.1） | 业务主后端；当前补丁在 G0 复核 |
| Agent | Python 3.12、FastAPI（观察到 0.148.0）、LangGraph 1.2.x（观察到 1.2.16） | 版本锁定；FastAPI 管内部 REST，LangGraph 管有状态图 |
| Web | Vue 3.5.x + TypeScript | 不采用 3.6 RC 作为稳定基线 |
| 数据库 | PostgreSQL 17 | 业务和 LangGraph checkpoint 共用实例，分 schema/账户权限 |
| 容器 | Docker Compose | Kuma 使用可选 profile；锁定明确版本/digest，不用 `latest` |

LangGraph 采用开源 Python 库和 Postgres checkpointer，不依赖 LangSmith/LangGraph Platform 云托管能力。**只有 Agent Service 调用模型**；Spring Boot 不连接模型。模型配置和密钥仅由 Agent Service 持有，provider 可插拔；`mock` 模式本地默认启用。

## 架构取舍

- **业务边界放在 Java**，符合目标岗位路线且确保权限/事务/审计集中。
- **Agent 独立 Python 服务**，利用 Python/LangGraph 表达图状态和节点；内部契约稳定、业务由 Java 决定。
- **PostgreSQL Outbox** 代替独立消息代理；单机部署轻量，同时保留至少一次投递。
- **服务探测走专用 scheduler**，只执行登记目标的轻量 HTTP GET/HEAD；不尝试复制 Prometheus、Zabbix 等完整监控平台。
- **Kuma 可选外部面板**，Push Token 用于单向状态投递；Push API 属于上游内部接口，故 adapter 需可关闭且做版本契约检查。
