# 01｜项目章程与 PRD

## 项目章程

| 项目项 | 决策 |
|---|---|
| 名称 | AgentOps AI 智能运维平台（B） |
| 目标 | 为小型开发团队汇总健康检查、事故记录、运行手册和可审查的 AI 诊断建议 |
| 用户 | 值班工程师、运维管理员、只读观察者、审计员 |
| 形态 | 单组织、自托管、本地演示优先；可选连接单实例 Uptime Kuma |
| 主业务技术 | Java 21、Spring Boot 4.1.x、PostgreSQL 17 |
| Agent 技术 | Python 3.12、FastAPI、LangGraph 1.2.x |
| 前端 | Vue 3.5.x + TypeScript |
| 规模假设 | 10 个登记目标、每个目标 1 分钟以上检查间隔、单实例服务 |

## 产品问题与方案

小型团队的健康信号、事故历史和处理手册分散，值班人员难以快速解释“发生了什么、有哪些证据、接下来应检查什么”。系统收集登记服务的 HTTP 检查结果，基于时间窗口聚合事故，再让 Agent 按固定图读取服务元信息/检查历史/授权手册并写出带证据的建议。

Uptime Kuma 是可选的现有监控面板：Operator 在 Kuma 手工创建 Push Monitor，把 Push Token 配置到对应目标；AgentOps 将自己的检查状态推送给 Kuma。AgentOps 自身数据不依赖 Kuma 回读。

## MVP

- 用户/角色、服务目标、HTTP 检查策略、最近结果与事故列表。
- 事故确认、处理记录、手工解决、时间线和运行手册管理。
- Agent 诊断启动、运行阶段、证据引用、建议、人工审批/拒绝记录。
- `mock` 模型、固定场景评测、可选 Kuma 推送、审计、Compose 和 CI。

## 非目标和反目标

- 不做 AIOps 平台替代、指标/日志/链路全量采集，不接管 Kubernetes 或云账号。
- 不做生产级 HA、SLA 商业承诺、多租户计费、CMDB 自动发现或任意插件市场。
- 不执行模型生成的命令，不自动重启/扩容/修改生产配置，不把用户日志发送给模型前隐藏安全边界。
- 失败条件：任意 URL 探测形成 SSRF；Agent 伪造证据；Kuma 故障导致事故数据丢失；工具越过只读范围；审批无法追溯。

## 成功场景

值班工程师在系统看到某服务连续失败→打开事故→请求诊断→Agent 引用近 10 次探测结果和授权运行手册，返回事实、假设、置信度和下一步检查→工程师审阅/拒绝/标记已按手册执行→事故状态与审计可追踪。以上只描述预期验收路径。
