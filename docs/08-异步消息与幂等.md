# 08｜异步消息、幂等与恢复

## Outbox 主流程

检查结果、事故变更或 AgentRun 创建与 Outbox 事件写在同一个 PostgreSQL 事务。worker 用 `FOR UPDATE SKIP LOCKED` 领取事件、加租约、事务外调用目标/Agent/Kuma，完成后回写状态。没有额外 broker，适合单机本地实现。

## 事件类型

| 事件 | 消费者 | 幂等规则 |
|---|---|---|
| `CHECK_DUE` | Java checker | `(checkDefinitionId, scheduledAtBucket)` 唯一；错过多个周期不补发风暴，只执行一次并记 skipped |
| `CHECK_COMPLETED` | Incident evaluator、Kuma adapter | CheckRun ID 唯一；重复评估不重复创建事故/恢复事件 |
| `AGENT_RUN_REQUESTED` | Python Agent API | `runId` 和 `thread_id` 唯一；相同 run 重放返回既有状态 |
| `AGENT_RUN_COMPLETED` | Java result handler | 只接受对应 runId/graphVersion 的首个终态；重复回调无副作用 |
| `KUMA_PUSH_REQUESTED` | Kuma adapter | `checkRunId` 唯一；重复推送保留原状态并记录 attempt |

## 重试策略

- 默认 2s、10s、60s、5m 指数退避 + 抖动，最多 5 次；超限 `DEAD`，管理员明确重试。
- 4xx 格式/权限/目标被策略拒绝不重试；429/5xx/网络超时有限重试。
- LangGraph checkpointer 用 `thread_id=agentRunId`；相同线程恢复已保存状态。Java 对 Agent 完成结果进行 JSON schema 与 evidence ID 验证后落库。
- Kuma 推送失败不回滚 CheckRun 或 Incident；仅更新 IntegrationDelivery 并显示警告。
- worker 崩溃时租约过期后可由下一实例接管；处理结果与 outbox 状态原子完成。

## 幂等键

- 创建型写 API 使用 `api_idempotency(user_id, operation, idempotency_key)` 和带用途隔离的请求 HMAC-SHA256 指纹；密钥来自数据库外的服务端 pepper。同指纹重放返回同一资源 ID/状态码并重新鉴权，不同指纹返回 409，处理中返回 409 + 可重试提示。包含密码的用户创建请求不得使用无密钥 SHA-256，以免产生比 bcrypt 更廉价的离线密码校验器。仅存 2xx 状态码与资源 ID、不缓存正文，保留 24 小时后清理；键领取与业务写入同事务。
- 检查：`checkDefinitionId + scheduledAtBucket`。
- Agent：前端请求键 + `(incidentId, requestId)`；同一 Idempotency-Key 返回既有 run，不重复计模型费用。
- 集成：`integrationId + checkRunId`。
- 事故：同目标只能有一个活动事故的部分唯一索引；并发创建冲突后查询并关联既有事故。
- 审批：`approvalRequestId + decisionVersion`，只接受一次终态决策。

## 监控与排障

记录 pending 数、最老 Outbox 年龄、失败码、dead 数、Agent 图各节点时长、Kuma push 成功率。只记录 ID、状态和必要摘要；正文和密钥不进标签。恢复流程应支持暂停某 consumer、修复配置、查看脱敏事件并人工重试。

## G4 人审投递实现

同一个run的Outbox行按INVOKE→DONE→RESUME→DONE演进，超期转CANCEL；每次进入新阶段重置尝试次数，但不丢弃input/result/决定。HTTP仍在事务外执行。INVOKE分发检查原发起者权限，RESUME检查审阅者当前值班/目标操作权限；撤权后DEAD保留决定，管理员恢复重试不绕过权限。CANCEL是系统过期操作，不依赖原用户仍有权限。

Python先持久化不可变决定，再Command(resume)；在这两个提交之间崩溃可用相同请求恢复。advisory lock串行化同run，checkpoint已进入finalize或终态时不再调用analyze。G3输入指纹的旧规范继续兼容，新modelName不会使旧任务重放误报409。工作者启用时每3秒检查到期请求；决定接口也先执行到期处理，并在锁后按数据库真实时钟拒绝迟到决定。

模型调用自身也有持久化journal：外部HTTP前提交STARTED，结果经schema/引用/风险校验后提交COMPLETED及原报告，最后才让LangGraph保存analyze checkpoint。图checkpoint失败后恢复读COMPLETED缓存，不二次请求模型；如完成情况不明则保留STARTED、返回MODEL_OUTCOME_UNKNOWN并停止该run的自动和管理员重发。远端HTTP与本地PG不能原子提交，本方案选择显式暴露不确定状态；已知429/5xx/连接拒绝可回到RETRYABLE，按现有策略恢复，不把远端计费的exactly-once当作已有保证。
